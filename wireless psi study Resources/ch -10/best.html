1. પરિચય (Introduction)

🤔 આ શું છે?

Android એ Google દ્વારા બનાવવામાં આવેલું મોબાઇલ ઓપરેટિંગ સિસ્ટમ છે.

📝 સરળ વ્યાખ્યા

એક એવું સોફ્ટવેર જે તમારા ફોનને ચલાવે છે અને એપ્સને કામ કરવા દે છે.

રોજિંદા ઉદાહરણ:
• જેમ શરીરમાં મગજ કામ કરે છે, તેમ ફોનમાં Android કામ કરે છે.
• જેમ ઘરમાં વીજળીનું વાયરિંગ બધા ઉપકરણોને જોડે છે, તેમ Android બધી એપ્સને ફોન સાથે જોડે છે.

🎯 તેનો અર્થ

  • Open Source – કોઈ પણ વ્યક્તિ તેને જોઈ, બદલી અને વાપરી શકે છે.
  • Linux-based – તે Linux નામના બીજા સિસ્ટમ પર બનેલું છે.
  • Mobile OS – ખાસ મોબાઇલ ફોન માટે બનાવેલું.

❓ શા માટે જરૂરી છે?

  • ફોનને સમજવા માટે
  • એપ્સ ચલાવવા માટે
  • હાર્ડવેર (કેમેરા, સ્ક્રીન, બ્લૂટૂથ)ને કંટ્રોલ કરવા

📍 ઉપયોગ ક્યાં થાય છે?

સ્થળ ઉપયોગ
📱 Smartphones વોટ્સએપ, ઇન્સ્ટાગ્રામ, ગેમ્સ

3. Android Architecture

🏗️ 5 Layers Architecture (Bottom → Top)

┌─────────────────────────────────────────────┐ │ 🟢 APPLICATIONS LAYER │ ← Top │ (Dialer, Camera, WhatsApp, Games) │ ├─────────────────────────────────────────────┤ │ 🟡 APPLICATION FRAMEWORK │ │ (Activity Manager, Content Providers, │ │ View System, Notification Manager) │ ├─────────────────────────────────────────────┤ │ 🟠 LIBRARIES + ANDROID RUNTIME (ART) │ │ (SQLite, WebKit, OpenGL, Media, ART) │ ├─────────────────────────────────────────────┤ │ 🔵 HARDWARE ABSTRACTION LAYER (HAL) │ │ (Camera, Bluetooth, Audio, Sensors) │ ├─────────────────────────────────────────────┤ │ 🔴 LINUX KERNEL │ ← Bottom │ (Security, Memory, Process, Drivers) │ └─────────────────────────────────────────────┘

🔴 Linux Kernel (Base Layer)

  • 🔒 Security – ફોનને સુરક્ષિત રાખે
  • 💾 Memory Management – RAM મેનેજ કરે
  • ⚙️ Process Management – કઈ એપ ક્યારે ચાલે
  • 📡 Drivers – કેમેરા, Wi-Fi, Bluetooth ને કંટ્રોલ કરે
રોજિંદું ઉદાહરણ: જેમ ઘરનો પાયો આખું ઘર ટકાવે, તેમ Linux Kernel આખા Android સિસ્ટમને ટકાવે છે.

🔵 Hardware Abstraction Layer (HAL)

કેમેરા, બ્લૂટૂથ, Audio, Sensors માટે Standard Interface આપે. Android Framework ને Hardware થી અલગ રાખે.

રોજિંદું ઉદાહરણ: જેમ અનુવાદક બે વ્યક્તિ વચ્ચે વાત કરાવે, તેમ HAL Hardware અને Android વચ્ચે વાત કરાવે છે.

🟠 Android Runtime (ART) & Native Libraries

Dalvik vs ART:

Dalvik (Old) ART (New – Android 5.0+)
JIT (Just-In-Time) AOT (Ahead-Of-Time)
એપ ચાલતી વખતે કોડ કન્વર્ટ થાય ઇન્સ્ટોલ થતાં જ કોડ કન્વર્ટ થાય
ધીમું ઝડપી ⚡
વધુ Battery વપરાશ ઓછો Battery વપરાશ
રોજિંદું ઉદાહરણ: Dalvik = રસ્તા પર ચાલતી વખતે નકશો વાંચવો (ધીમું); ART = જતાં પહેલાં રસ્તો યાદ કરી લેવો (ઝડપી).

Native Libraries

Library કામ

OpenGL ES 2D/3D Graphics (ગેમ્સ, Animation)

"Little Hardware Requires Fast Apps"

4. Activities, Lifecycle & Intent

🖥️ Activity શું છે?

Activity = એક સ્ક્રીન (e.g., WhatsApp Chat Screen, Settings Screen).

AndroidManifest.xml માં Declare કરવી:

<activity android:name=".MainActivity"> <intent-filter> <action android:name="android.intent.action.MAIN" /> <category android:name="android.intent.category.LAUNCHER" /> </intent-filter> </activity>

🔄 Activity Lifecycle (7 Methods)

"Cops Start Running Past Suspect's Door"
Method ક્યારે Call થાય શું કરવું?
onCreate() પહેલીવાર બને ત્યારે UI Setup (setContentView)
onStart() User ને Visible થાય
onResume() User Interact કરી શકે App ચાલુ કરો
onPause() બીજી Activity આવે (Partial Cover) Data Save કરો
onStop() સંપૂર્ણ Hidden થાય Heavy Work રોકો
onRestart() Stop થયા પછી ફરી શરૂ થાય
onDestroy() Memory માંથી Remove થાય Cleanup કરો
onCreate() → onStart() → onResume() → (Running) ↓ onPause() ↓ onStop() ↙ ↘ onRestart() onDestroy() ↓ onStart()
🎯 Golden Rule: onPause() = Partial Visible, onStop() = Completely Hidden.

🎭 Intent

Intent = મેસેજ જે એક Activity થી બીજી Activity માં જાય છે.

Type શું છે? ઉદાહરણ
Explicit Intent ચોક્કસ Activity ખોલે MainActivity → SecondActivity
Implicit Intent System યોગ્ય Activity શોધે "View Map" → Google Maps
// Explicit Intent intent = new Intent(MainActivity.this, SecondActivity.class); startActivity(intent); // Implicit Intent intent = new Intent(Intent.ACTION_VIEW, Uri.parse("https://gujaratpolice.gujarat.gov.in")); startActivity(intent);

📚 Launch Modes

Mode શું કરે?
standard દર વખતે નવી Activity બને
singleTop ટોચ પર હોય તો નવી ન બને

⚠️ ANR (Application Not Responding)

9. Working with Database (SQLite)

📊 SQLite શું છે?

Lightweight, Server-less, Zero Configuration, Single File Database. રોજિંદું ઉદાહરણ: જેમ ડાયરીમાં નોંધ લખો, તેમ SQLite ફોનમાં Data સેવ કરે છે.

🔧 SQLiteOpenHelper – "C.U.D."

Method ક્યારે Call થાય? શું કરે?
C → onCreate() પહેલીવાર Database બને Tables Create કરે
U → onUpgrade() Version વધે Schema Update કરે
D → onDowngrade() Version ઘટે Schema Downgrade કરે
public class DBHelper extends SQLiteOpenHelper { private static final String DB_NAME = "MyDatabase.db"; private static final int DB_VERSION = 1; @Override public void onCreate(SQLiteDatabase db) { String CREATE_TABLE = "CREATE TABLE Student(" + "id INTEGER PRIMARY KEY AUTOINCREMENT," + "name TEXT," + "marks INTEGER)"; db.execSQL(CREATE_TABLE); } }

✏️ CRUD Operations

Operation Method ઉદાહરણ
Create insert() db.insert("Student", null, cv)
Read rawQuery() db.rawQuery("SELECT * FROM Student", null)
Update update() db.update("Student", cv, "id=?", new String[]{"1"})
Delete delete() db.delete("Student", "id=?", new String[]{"1"})

🔍 SQL Injection Protection

// ✅ Safe – Using Selection Arguments db.rawQuery("SELECT * FROM users WHERE name = ?", new String[]{"Raj"});

📌 Cursor Golden Rule

Always call cursor.moveToFirst() before reading data! Without it → CursorIndexOutOfBoundsException.
Cursor cursor = db.rawQuery("SELECT * FROM Student", null); if (cursor.moveToFirst()) { String name = cursor.getString(cursor.getColumnIndex("name")); } cursor.close(); // Always close cursor!

🚀 Advanced Trends

Keyword શું છે? (વિગતવાર વન-લાઇનર અને ઉદાહરણ)
Room વન-લાઇનર: એન્ડ્રોઇડમાં ડેટાબેઝ (SQLite) વાપરવા માટે ગૂગલ દ્વારા બનાવવામાં આવેલું એક સરળ અને આધુનિક કવર (Jetpack Component / Abstraction Layer).

ઉદાહરણ: પહેલાના સમયમાં ડેટાબેઝ બનાવવા માટે લાંબો અને અઘરો કોડ લખવો પડતો હતો, પરંતુ Room ની મદદથી તમે ખૂબ જ ઓછા અને સાદા કોડથી મોબાઈલની અંદર ડેટા કાયમ માટે સેવ કરી શકો છો (જેમ કે યુઝર પ્રોફાઇલ કે ઑફલાઇન ચેટ્સ).
DAO વન-લાઇનર: Data Access Object - ડેટાબેઝમાં ડેટા ઉમેરવા, સુધારવા કે ડીલીટ કરવા માટેની ક્વેરીઝ (Queries) લખવાની જગ્યા અથવા ઇન્ટરફેસ.

ઉદાહરણ: આ એક એવા મેનેજર જેવું છે જેને તમે ઓર્ડર આપો કે "નવો યુઝર ઉમેરો" અથવા "બધા ગુનેગારોનું લિસ્ટ લાવો", એટલે તે બેકગ્રાઉન્ડમાં જઈને ડેટાબેઝમાંથી એ કામ કરી આપે. આના માટે આપણે @Insert અથવા @Query જેવા ટેગ વાપરીએ છીએ.
Entity વન-લાઇનર: ડેટાબેઝની અંદર બનનારા ટેબલ (Table) ને દર્શાવતો એક સાદો ક્લાસ (Class).

ઉદાહરણ: જો તમારે યુઝરનો ડેટા સાચવવો હોય, તો તમે User નામનો એક ક્લાસ બનાવશો જેમાં id, name અને phone વેરિએબલ હશે. Room આ ક્લાસને જોઈને ઓટોમેટિક ડેટાબેઝમાં User નામનું ટેબલ અને તેના કોલમ બનાવી દેશે.
SQLCipher વન-લાઇનર: રૂમ ડેટાબેઝની આખેઆખી ફાઇલને કોઈ ચોરી ન શકે તે માટે તેને 256-bit AES એન્ક્રિપ્શન થી સુરક્ષિત (લોક) કરતું સોફ્ટવેર.

ઉદાહરણ: જો કોઈ પોલીસ એપનો ડેટાબેઝ હોય, તો SQLCipher વગર કોઈ પણ હેકર ફોનમાંથી એ ફાઇલ ખોલીને બધી વિગતો વાંચી શકે છે. પણ આ ફીચર ચાલુ કરવાથી, પાસવર્ડ કે કી વગર ડેટાબેઝ ઓપન જ થતો નથી, બધું લખાણ લોક થઈ જાય છે.

10. Gujarat Police Context

📱 Police Mobile Applications

  • "Pocket Cop" – Mobile Data Terminals (MDTs)
    -> ઓન-ફિલ્ડ ઉભેલા પોલીસ અધિકારીઓ માટે રસ્તા પર જ લાઈવ ડેટા ચેક કરવાનું મિની-કોમ્પ્યુટર.
    ઉદાહરણ: રાત્રે નાકાબંધી દરમિયાન પોલીસે કોઈ શંકાસ્પદ ગાડી રોકી, તો Pocket Cop એપમાં તેનો નંબર નાખતા જ લાઈવ ખબર પડી જશે કે ગાડી ચોરીની છે કે નહીં.

  • e-Challan – Digital Traffic Challan
    -> ટ્રાફિકના નિયમો તોડનારા લોકો માટેનું ઓનલાઈન અને પેપરલેસ દંડ મશીન.
    ઉદાહરણ: જો કોઈ વ્યક્તિ હેલ્મેટ વગર સિગ્નલ ક્રોસ કરે, તો સીસીટીવી કેમેરા તેનો નંબર સ્કેન કરીને સીધો જ તેના મોબાઈલ પર ઈ-મેમો (દંડ) મોકલી દે છે.

  • FIR System – Digital FIR Registration
    -> કોઈપણ ગુનાની પ્રાથમિક ફરિયાદ (FIR) ચોપડાના બદલે સીધી ઓનલાઈન અને સેફ સર્વર પર નોંધવાની સિસ્ટમ.
    ઉદાહરણ: કોઈ મોટી ચોરી કે અકસ્માત થાય ત્યારે પોલીસ ઘટનાસ્થળેથી જ ટેબ્લેટ દ્વારા લાઈવ FIR લોક કરી શકે છે, જેથી ડેટામાં કોઈ છેડચાડ ન થઈ શકે.

  • Biometric API – Fingerprint Scanners with Criminal Databases
    -> મોબાઈલ સ્કેનર પર અંગૂઠાની છાપ લઈ સેકન્ડોમાં ગુનેગારનો રેકોર્ડ શોધવાની ટેક્નોલોજી.
    ઉદાહરણ: રસ્તા પર કોઈ શંકાસ્પદ વ્યક્તિ પોતાનું ખોટું નામ બતાવે, ત્યારે પોલીસ તેના ફિંગરપ્રિન્ટ સ્કેન કરીને સેન્ટ્રલ ડેટાબેઝમાંથી તેની અસલી કુંડળી અને ક્રિમિનલ હિસ્ટ્રી બહાર કાઢી લે છે.

  • e-GujCop – Police Database Integration
    -> આખા ગુજરાતના તમામ પોલીસ સ્ટેશનો અને ડેટાને એકબીજા સાથે જોડતું વિશાળ ડિજિટલ નેટવર્ક.
    ઉદાહરણ: જો કોઈ ગુનેગાર અમદાવાદમાં ચોરી કરીને રાજકોટ ભાગી જાય, તો રાજકોટ પોલીસ e-GujCop માં સર્ચ કરીને તેની સામે થયેલી અમદાવાદની FIR અને તેનો ફોટો લાઈવ જોઈ શકે છે.

  • MDM (Mobile Device Management)
    -> ઓફિસમાંથી જ પોલીસના ફોનને રિમોટલી કંટ્રોલ અને લોક કરવા માટેનું સોફ્ટવેર.
    ઉદાહરણ: જો કોઈ પોલીસ અધિકારીનો ફોન ખોવાઈ જાય, તો હેડ-ઓફિસ ત્યાં બેઠા-બેઠા જ એ ફોનનો બધો જ ડેટા ડિલીટ (Wipe) કરી શકે છે જેથી કોઈના હાથમાં ન આવે.

  • SQLCipher
    -> મોબાઈલની અંદર સ્ટોર થતા ડેટાબેઝને મજબૂત તાળું (256-bit AES Encryption) મારવા માટે.
    ઉદાહરણ: એપમાં સચવાયેલું ગુનેગારોનું લિસ્ટ જો કોઈ હેકર ચોરી પણ લે, તો પણ પાસવર્ડ (Key) વગર તેને ખોલી શકતો નથી, તેને બધું અવાચ્ય કચરા (Gibberish) જેવું દેખાશે.

  • Project Treble
    -> ફોનમાં ગૂગલ તરફથી આવતા સિક્યોરિટી અપડેટ્સ ખૂબ જ ઝડપથી ઇન્સ્ટોલ કરવાની સિસ્ટમ.
    ઉદાહરણ: જ્યારે કોઈ નવો ખતરનાક વાયરસ માર્કેટમાં આવે, ત્યારે મહિનાઓ સુધી રાહ જોયા વગર ફોનમાં ૨ જ દિવસમાં નવો સિક્યોરિટી પેચ (પ્રોટેક્શન) અપડેટ થઈ જાય છે.

  • BiometricPrompt
    -> ફોનના ફિંગરપ્રિન્ટ કે ફેસ લોક સેન્સરનો ઉપયોગ કરીને એપને સુરક્ષિત રીતે ઓપન કરવાની સિસ્ટમ.
    ઉદાહરણ: પોલીસ અધિકારી જ્યારે 'Pocket Cop' એપ ઓપન કરે, ત્યારે દર વખતે પાસવર્ડ ટાઈપ કરવાના બદલે માત્ર અંગૂઠો (Fingerprint) અડાડીને સેકન્ડમાં લોગિન કરી શકે છે.

11. Formula Sheet & Calculations

📐 DP to PX

px = dp × (dpi / 160)

યાદ રાખો: 160 dpi પર, 1 dp = 1 px

🧮 DPI Calculation

DPI = √(Width² + Height²) / Diagonal Size (inches)

ઉદાહરણ: 1080×1920, 5 inch → DPI = 440.58 (xxhdpi)

📏 Scale Factor Example

xxhdpi (Scale factor = 3.0): 100dp → 100 × 3.0 = 300 px

📊 Memory Size Calculations

Scenario Calculation Result
10,000 integers (16 bytes each) 10,000 × 16 160 KB
100×100 Bitmap (ARGB_8888, 4 bytes/pixel) 10,000 × 4 ~40 KB
2 MB CursorWindow, 500 KB BLOB rows 2048 / 500 4 rows
400ms query, 60Hz (16.6ms/frame) 400 / 16.67 ~24 frames skipped
